Developer Notes

The browser remains fully offline. Full-resolution images use temporary object URLs; bounded JPEG previews are stored in projects.

Version 1.9.1 maintains a bounded 100-entry history of serialized project-data snapshots. Transient UI state is excluded. A saved snapshot fingerprint lets Undo and Redo return the save-state indicator to Saved when the current data exactly matches the last explicit project save.

Recovery records use the PhotoStoryCreatorRecovery IndexedDB database and contain a record ID, schema number, application version, project name, timestamp, and project snapshot. IndexedDB avoids the small local-storage quota that prevented large thumbnail-rich projects from being protected. Recovery is debounced after edits, excludes temporary File objects and object URLs, and is cleared by an explicit save or discard. A generation counter prevents an in-flight write from recreating a recovery record after Undo or Save clears it. Startup never restores recovery silently. A legacy local-storage record from the first v1.9.1 test package is migrated when present.

Version 1.8 adds a canvas-based transform workspace. Control changes remain drafts until an explicit current-image or selected-image Apply action writes the per-image transform object. The preview and transformed-copy export use the project resolution, scale mode, and background. Export uses browser JPEG/PNG encoding and never obtains a writable handle to the source photograph.

Version 1.7.2 timing remains intact: every image keeps its full logical hold and animated transitions are additive intervals. FFmpeg still uses xfade; generated clip durations include the incoming visible transition and the following transition's technical tail so the composed duration equals holds plus visible transitions. Frame-safe simulated Cuts remain zero-duration in the user timing model.

Automatic motion is deterministic and transforms are applied before motion processing. Zooms use a 2× output-size working canvas to reduce integer stepping, then emit the selected resolution and frame rate. Pans and static slides remain at final resolution. Linux render clips use project-setting fingerprints so unchanged completed clips survive interrupted runs.

File soundtracks are repeated through a dynamically generated acrossfade graph. Repetition count accounts for overlap, crossfade length is capped at half the source duration, and the combined audio is trimmed to the exact story runtime before its final fade.

Relinking records the selected directory as imageFolder and stores each matched image path relative to that root.

The slideshow preview derives a read-only additive timeline from live project state and uses browser animations to approximate FFmpeg motion and transitions.

Older projects receive safe defaults. Source image bytes are never modified by transforms.
